# `harness-installers/standard/`

The npm release channel: a self-contained package published as **`rad-orc`**, run by end users as
`npx rad-orc`. It is the only build that produces **every harness in one pass**, and the only
one whose install manifests are generated rather than hand-authored. Contributors landing here are
authoring the end-user install and uninstall experience.

## How it works

| Path | Holds |
|---|---|
| `index.js` | The `rad-orc` binary. Parses argv, runs the tooling checks, drives the wizard, then loops `installHarness` and calls `hydrateUserData` once |
| `lib/wizard.js` | The interactive picker. Install or uninstall, one harness per run, plus the confirmation prompts |
| [`lib/install/`](./lib/install/AGENTS.md) | The install and uninstall state machine, and everything that touches a user's disk |
| [`lib/checks/`](./lib/checks/AGENTS.md) | Pre-flight tooling probes |
| [`build-scripts/`](./build-scripts/AGENTS.md) | `build.js`, `validate.js`, `emit-manifest.js`, `check-manifest-drift.mjs` |
| `manifests/<harness>/v<version>.json` | **Tracked, committed** path catalogs — generated by the build |
| `output/` | Gitignored build payload; the tarball's contents |
| `tests/` | `node:test`, split into `build/`, `helpers/`, `install/`, `integration/`, `lib/` |

The wizard collects **only** an action and a harness. Review tiers, gate behaviour, and auto-commit
settings are never prompted — they ship verbatim from `runtime-config/orchestration.yml`. There is no
config generator.

The dashboard is **not optional**: `hydrateUserData` extracts `ui.tgz` into `~/.radorc/ui/` on every
install, with no wizard question behind it.

## Conventions

- **ESM only, Node 18+.** `.js` in `lib/` and `index.js`, `.mjs` in `tests/` for the `node --test`
  runner. No transpile step, no backports.
- **No test-only branches in production code.** Test doubles are injected through `opts` — every
  entry point in `lib/install/` takes its roots and paths as parameters. Never add an
  `if (process.env.NODE_ENV === 'test')`.
- **Post-install warnings never halt the flow.** Missing tooling, coexistence notices, and drift
  hints go to stderr and the install continues with a non-error exit code.
- **`install.json` is the answer to "is this harness installed?"** Nothing infers installation state
  from the presence of files, and only `lib/install/` writes it.

### Atomicity is per writer, not blanket

Tmp-write-then-rename is used by `install.json` (`install-json.js`), Claude's `settings.json`
(`claude-hook-settings.js`), the generated manifests (`emit-manifest.js`), and the `~/.radorc/ui/`
replacement in `hydrate-user-data.js`. Manifest-driven file copying is **not** atomic — `install-files.js`
copies entry by entry. Do not describe this package as writing atomically without saying which write.

## Hook registration into a user-owned `settings.json`

For the **Claude harness only**, install merges hook entries into `~/.claude/settings.json`, a file
the user owns and edits. Copilot harnesses get their shims placed by the manifest and need no
settings surgery.

Entries are located by a **marker substring embedded in the command string**, not by a metadata
field — `rad-orc-preamble` for the `SessionStart` preamble, `rad-orc-telemetry` for the telemetry
set. That is what makes install idempotent, makes a partial install self-heal, and makes uninstall
able to remove exactly what this installer added while leaving every other hook entry, and every
other settings key, untouched. The marker families are deliberately distinct: removing the
telemetry entries never disturbs `SessionStart`, and removing the preamble never disturbs the
telemetry events.

The functions are `mergePreambleHook`, `removePreambleHook`, `reconcileTelemetryHooks`, and
`removeTelemetryHooks`, all in `lib/install/claude-hook-settings.js`. **Never write to a user's
`settings.json` any other way**, and never widen a filter to something that could match a
hand-authored entry.

## Hazards

### `manifests/` is committed output that lands in the PR diff

The build writes `manifests/<harness>/v<version>.json` into the source tree, not into `output/`, and
`npm run check:manifest-drift` fails CI when what is committed does not match a rebuild. Reverting
that diff, or gitignoring the folder, breaks the gate and breaks uninstall on real machines.

**Never delete an older `v*.json`.** An upgrade loads the *installed* version's manifest to remove
its files before installing the new set, and every prior manifest is copied forward into the payload
for exactly that reason.

### `npm pack` runs from `standard/`, not from `output/`

The publish `package.json` is this folder's own, so there is no synthesized output-side manifest and
the size budget in `validate.js` is measured from here. Anything that changes what `files` includes,
or adds weight anywhere under `standard/`, moves that gate.

### Content tokens are expanded only under `agents/` and `skills/`

`${PLUGIN_ROOT}` and `${SKILLS_ROOT}` are resolved at **install** time, against the installing user's
home — never baked at build time, because `output/` ships prebuilt and baking would embed the build
machine's home directory into every user's files. The expansion is scoped by bundle-path prefix. A
token written into an action-event file, a communication style, a tier template, a hook shim, or a
doc page ships **literally** to the user's disk. No build error, no test.

### The UI tarball unpacks one level deeper than it looks

Next's standalone output nests the app under its own directory, so `~/.radorc/ui/` ends up holding
`ui/server.js` — the server entry is `~/.radorc/ui/ui/server.js`. `cli/src/commands/ui/start.ts`
hardcodes that path to match. The contract lives in a comment in `emit-ui-bundle.js` and in that one
`path.join`; changing the packed layout breaks `radorch ui start` with nothing in between to catch
it.

### Installing one Copilot variant evicts the other

`copilot-cli` and `copilot-vscode` share `~/.copilot/` with incompatible agent content, so installing
either removes the other's registry entry. Plugin-channel entries are never evicted — they are
preserved and surfaced as a coexistence warning instead.

### `RADORCH_PACKAGE_ROOT` relocates the entire bundle root

`index.js` reads it as an override for the package directory that both the per-harness payloads and
the shared `output/` are resolved against. It is undocumented on the user-facing surface; treat it as
a test and dogfood affordance, and remember it exists before concluding a path is fixed.

## When a change here ripples

- **Changed what lands in `output/`, or added, renamed, or deleted a file that ships?** The manifests
  are path catalogs and **uninstall removes only what a manifest recorded**. Rebuild and commit the
  manifest diff in the same change; `npm run check:manifest-drift` is the CI gate. Not everything
  under `output/` is manifest-managed, though: `orchestration.yml`, `templates/`, and `ui/` are
  excluded by design and installed by the hydration step, so changing one produces no manifest diff.
  Neither does editing a shipped file's *content*. Absence of a diff in those cases is correct, not a
  miss. Detail:
  [`build-scripts/AGENTS.md`](./build-scripts/AGENTS.md),
  [`harness-files/AGENTS.md`](../../harness-files/AGENTS.md)

- **Adding a harness?** It is a multi-file change and every miss is silent. The builder's `HARNESSES`
  constant and the `validate` step's `harnesses` argument; `validate.js`'s agent-filename suffix set;
  `harness-paths.js`'s folder map; `install-json.js`'s `INSTALL_KEYS`, `FOLDER_MUTEX_PARTNERS`, and
  `PLUGIN_COEXIST_PARTNERS`; the wizard's choice and display tables; and a new
  `manifests/<harness>/` folder. Detail: [`lib/install/AGENTS.md`](./lib/install/AGENTS.md),
  [`harness-adapters/AGENTS.md`](../../harness-adapters/AGENTS.md)

- **Changed which hook events are wired, or the shim filenames the settings entries point at?** The
  shims are single-sourced in `shared/hooks/` and staged by the build; the `settings.json` entries
  written here embed their absolute install-time paths. A shim renamed on one side and not the other
  leaves a hook command pointing at nothing, and the hook fails silently. Detail:
  [`../shared/hooks/AGENTS.md`](../shared/hooks/AGENTS.md),
  [`docs/internals/ambient-awareness.md`](../../docs/internals/ambient-awareness.md)

## Commands

```
npm run build -w harness-installers/standard
npm test -w harness-installers/standard
npm run check:manifest-drift -w harness-installers/standard
```

**Never run the installer against your real home directory to exercise a change** — `~/.radorc/`,
`~/.claude/`, and `~/.copilot/` are not sandboxed. The suites inject a temp home; use them, or use
the `/rad-dogfood-harness` skill, which drives the full build-pack-reinstall cycle deliberately.
