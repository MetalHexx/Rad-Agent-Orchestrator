# rad-dogfood-plugin

Build one harness's greenfield plugin, stage it as a local dogfood marketplace, and hand
off install instructions for a fresh session. You do not install or verify the plugin
yourself — that happens in a separate session the user opens manually.

## Workflow

### Step 1 — Pick the variant

`AskUserQuestion`: `claude` / `copilot-cli` / `copilot-vscode`. Save as `{variant}`.

### Step 2 — Resolve repo root + fresh-clone guard

```
git rev-parse --show-toplevel
```

Use the result as `{repoRoot}`. The user is on Windows — backslash-separate paths in the
handoff message. The repo uses npm workspaces; `build.js` resolves `esbuild`/`next` from
the hoisted root `node_modules/.bin`, which doesn't exist on a fresh clone:

```powershell
if (-not (Test-Path (Join-Path "{repoRoot}" 'node_modules\.bin\next.cmd')) -and
    -not (Test-Path (Join-Path "{repoRoot}" 'node_modules\.bin\next'))) {
  npm install --prefix "{repoRoot}"
}
```

If `npm install` fails, stop and report.

### Step 3 — Build

```
node harness-installers/{variant}-plugin/build-scripts/build.js
```

From the repo root. Expect exit 0 and the build's `validate` step to report no missing
artifacts. A `Module not found: Can't resolve 'fsevents'` warning during `next build` is
cosmetic (macOS-only `chokidar` dep) — ignore it if the overall exit code is 0. If the
build fails, stop and report; do not continue.

### Step 4 — Verify the staged tree, capture `{version}`

| Variant | Manifest path |
|---|---|
| `claude` | `harness-installers/claude-plugin/output/.claude-plugin/plugin.json` |
| `copilot-cli` | `harness-installers/copilot-cli-plugin/output/plugin.json` |
| `copilot-vscode` | `harness-installers/copilot-vscode-plugin/output/.claude-plugin/plugin.json` |

Confirm `{repoRoot}/<manifest path>` exists and read its `version` field as `{version}`.
`copilot-cli` ships a root `plugin.json`; `claude` and `copilot-vscode` ship
`.claude-plugin/plugin.json` (Claude-format layout — this is what makes VS Code inject
`CLAUDE_PLUGIN_ROOT` so the plugin's hooks can self-locate). If the file is missing, stop
and report — the build silently produced an incomplete tree.

### Step 5 — Stage the dogfood marketplace

| Variant | Plugin dest folder | Marketplace name | marketplace.json path | `strict` field |
|---|---|---|---|---|
| `claude` | `plugins/rad-orc` | `rad-orc-dogfood` | `.claude-plugin/marketplace.json` | no |
| `copilot-cli` | `plugins/rad-orc` | `rad-orc-dogfood` | `.github/plugin/marketplace.json` | yes |
| `copilot-vscode` | `plugins/rad-orc-vscode` | `rad-orc-vscode-dogfood` | `.github/plugin/marketplace.json` | yes |

The dogfood marketplace lives at `{repoRoot}/harness-installers/{variant}-plugin/dogfood-marketplace/`,
a sibling of `output/`. The plugin must live under a `./`-relative subpath of the
marketplace root (Claude Code's marketplace spec forbids `../` and absolute `source`
paths; the other two harnesses follow the same shape here for consistency).

**(a) Copy the build output** — remove any prior copy first so stale files never linger:

```powershell
$mkt = "{repoRoot}\harness-installers\{variant}-plugin\dogfood-marketplace"
$pluginDest = "$mkt\{plugin dest folder, backslash-separated}"
if (Test-Path $pluginDest) { Remove-Item -Recurse -Force $pluginDest }
New-Item -ItemType Directory -Force -Path (Split-Path $pluginDest) | Out-Null
Copy-Item -Recurse -Force "{repoRoot}\harness-installers\{variant}-plugin\output" $pluginDest
```

Confirm the Step 4 manifest exists under `$pluginDest` after the copy.

**(b) Write `marketplace.json`** at the path from the table above (create nested dirs
first). Substitute the table's values; add `"strict": true` to the plugin entry only for
`copilot-cli`/`copilot-vscode`:

```json
{
  "name": "{marketplace name}",
  "owner": { "name": "radancy-pe" },
  "description": "Ephemeral local dogfood marketplace for the greenfield rad-orchestration {variant} plugin build. Generated by rad-dogfood-plugin skill; do not publish.",
  "plugins": [
    {
      "name": "{plugin name, e.g. rad-orc or rad-orc-vscode}",
      "source": "./{plugin dest folder}",
      "description": "Rad Orc multi-agent orchestration system for {harness label} (dogfood build)."
    }
  ]
}
```

Parse the written file back as JSON to confirm it's syntactically valid.

### Step 6 — Print install instructions

Substitute `{repoRoot}` and `{version}`; use backslash-separated Windows paths.

**`claude` / `copilot-cli`** — print, then continue to Step 7:

> The `{variant}` dogfood marketplace is staged. Plugin version: **`{version}`**.
>
> If a prior dogfood or legacy install of this harness's plugin is active, a coexistence
> warning may surface on first use in the new session — this is expected, not an error.
> For `claude` specifically, if the legacy `rad-test-plugin-release` marketplace
> (`rad-orchestration` / `rad-orchestration-dogfood`) is installed, remove it first:
> `/plugin uninstall rad-orchestration` then `/plugin marketplace remove rad-orchestration-dogfood`.
>
> Open a **fresh** session and run:
>
> `claude`: `/plugin marketplace add {repoRoot}\harness-installers\claude-plugin\dogfood-marketplace` then `/plugin install rad-orc@rad-orc-dogfood`
>
> `copilot-cli`: `copilot plugin marketplace add {repoRoot}\harness-installers\copilot-cli-plugin\dogfood-marketplace` then `copilot plugin install rad-orc@rad-orc-dogfood` (or `/plugin install rad-orc@rad-orc-dogfood` inside the session — the `@rad-orc-dogfood` qualifier is required, bare `rad-orc` fails).
>
> Reload if prompted. The bootstrap hook auto-populates `~/.radorc/` on your first prompt;
> the drift-check stays silent unless the cached plugin version differs from
> `~/.radorc/install.json`.
>
> Come back here when you're done dogfooding — I'll offer cleanup.

**`copilot-vscode`** — VS Code needs a method choice first. `AskUserQuestion`:

- **A — `chat.pluginLocations`** — lowest-friction: points VS Code straight at the plugin
  directory, no marketplace round-trip.
- **B — `chat.plugins.marketplaces` with a `file:///` URI** — registers the dogfood
  marketplace so the plugin appears in VS Code's Chat → Plugins UI like a published one.
- **C — `Chat: Install Plugin From Source`** — one-shot Command Palette install.

After the pick, print the matching block (all share the same coexistence-warning lead-in:
the standard installer's `copilot-vscode` target, or a Copilot CLI plugin VS Code
auto-discovers from `~/.copilot/installed-plugins/`, may trigger a bootstrap-hook
coexistence warning — expected, not an error):

> The VS Code dogfood marketplace is staged. Plugin version: **`{version}`**.
>
> **A:** Open VS Code's user settings JSON (Ctrl+Shift+P → "Open User Settings JSON") and add:
> `"chat.pluginLocations": { "{repoRoot}\\harness-installers\\copilot-vscode-plugin\\dogfood-marketplace\\plugins\\rad-orc-vscode": true }`
> Save; VS Code loads it on next chat session (restart if it doesn't appear under Chat → Plugins).
>
> **B:** Add a `file:///` entry to `chat.plugins.marketplaces` (forward-slashed, trailing
> slash required): `"file:///{repoRoot forward-slashed}/harness-installers/copilot-vscode-plugin/dogfood-marketplace/"`.
> Save, then install `rad-orc-vscode` from the `rad-orc-vscode-dogfood` marketplace via
> Chat → Plugins. To uninstall later: remove via that UI **and** remove the `file:///`
> entry, or the catalog keeps appearing.
>
> **C:** Command Palette → `Chat: Install Plugin From Source` → paste
> `{repoRoot}\harness-installers\copilot-vscode-plugin\dogfood-marketplace`.
>
> The bootstrap hook auto-populates `~/.radorc/` on your first prompt; the drift-check
> stays silent on a clean install.
>
> Come back here when you're done dogfooding — I'll offer cleanup.

### Step 7 — Wait, then offer cleanup

After printing instructions, wait for the user to say they're done, then `AskUserQuestion`
with both options surfaced explicitly:

- **Yes, clean up** — "Remove `{repoRoot}\harness-installers\{variant}-plugin\dogfood-marketplace`
  (the marketplace.json plus the staged plugin copy). The canonical build output at
  `output/` is untouched — re-running this skill regenerates everything from there."
- **Leave it for another round** — "Keep the dir so you can iterate; re-running this skill
  after a rebuild refreshes the plugin copy. Print the cleanup command for later."

**Clean up:**

```powershell
Remove-Item -Recurse -Force {repoRoot}\harness-installers\{variant}-plugin\dogfood-marketplace
```

Run it, confirm the directory is gone, and report that `output/` is untouched.

**Leave it:** print the command above for later. Also remind the user to uninstall from
the test session before switching channels — `/plugin uninstall rad-orc` (+ optionally
`/plugin marketplace remove rad-orc-dogfood`) for `claude`; `copilot plugin uninstall rad-orc`
for `copilot-cli`; for `copilot-vscode`, whichever of A (remove the settings entry) / B
(uninstall via Chat → Plugins UI and remove the `file:///` entry) / C (uninstall via
Chat → Plugins) matches the method they picked in Step 6.

That ends the skill. Do not run tests, npm pack, or other E2E validation — those belong
in CI or a separate workflow.
