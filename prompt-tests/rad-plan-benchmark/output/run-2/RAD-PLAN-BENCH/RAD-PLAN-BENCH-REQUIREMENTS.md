# RAD-PLAN-BENCH — Requirements

RAD-PLAN-BENCH is a tiny Node.js command-line program that prints "HELLO WORLD" as large, blocky ASCII-art letters, with each letter painted in a different color cycling through the rainbow spectrum. It runs once, prints its banner, and exits — no flags, no configuration, no interactive mode. The audience is anyone who wants an instantly satisfying, shareable terminal greeting, and the project doubles as a deliberately small end-to-end exercise of the orchestration pipeline.

Success is a single-command run (`node index.js` or `npm start`) that produces a centered, multi-line rainbow banner readable on common modern terminals, backed by a minimal-dependency codebase, at least one automated test, and a README that showcases the output. The work must stay simple enough to finish in a single sprint so the pipeline — not the problem — is what gets stress-tested.

## Goals

- Print "HELLO WORLD" as large ASCII-art letters that are clearly readable in a terminal.
- Color the banner across the full rainbow spectrum so it feels striking and shareable.
- Keep invocation to a single command that runs once and exits cleanly.
- Hold dependencies to the bare minimum (Node builtins plus `chalk` for color portability).
- Ship at least one automated test and a usage-focused README.

## Non-Goals

- Command-line flags or options (`--word`, `--style`, `--speed`).
- Configuration files or environment-driven behavior.
- Interactive mode, a shell, or any persistent process.
- Character-by-character or wave/animation reveal effects (static output only in v1).
- Guaranteed pixel-parity across every terminal; "readable on common modern terminals" is the bar.
- A web version, HTTP API, or any networked surface.

## Functional Requirements

### FR-1: ASCII-art HELLO WORLD banner
**Tags:** FR-1, ascii-art, rendering

The program renders the text "HELLO WORLD" as large, blocky ASCII-art glyphs spanning multiple terminal rows (3–5 lines tall), with every required letter glyph (H, E, L, O, W, R, D) and the inter-word space represented so the phrase reads clearly.

### FR-2: Rainbow per-letter coloring
**Tags:** FR-2, color, rainbow

Each rendered letter is emitted in a distinct color, advancing through the rainbow spectrum and looping back to the start once the spectrum is exhausted, so the full banner displays the complete color cycle.

### FR-3: Single-shot CLI invocation
**Tags:** FR-3, cli, entrypoint

A single command prints the banner once and the process exits cleanly with a success status. Both `node index.js` and `npm start` are supported entrypoints and produce identical output.

### FR-4: Automated output test
**Tags:** FR-4, testing, verification

At least one automated test exercises the banner-producing code and asserts a verifiable property of its output — for example that the rendered banner is non-empty, spans multiple lines, and contains ANSI color escape sequences.

### FR-5: Usage README
**Tags:** FR-5, docs, readme

The repository includes a README that states what the project does, how to install dependencies, how to run it (`node index.js` and `npm start`), and shows a sample of the rainbow ASCII-art output.

## Non-Functional Requirements

### NFR-1: Minimal dependency footprint
**Tags:** NFR-1, dependencies, simplicity

The runtime dependency set is limited to Node.js builtins plus `chalk` for cross-platform color. No additional production dependencies (including ASCII-art generators such as `figlet`) are introduced.

### NFR-2: Cross-platform terminal readability
**Tags:** NFR-2, portability, terminal

Colored output renders legibly on common modern terminals across macOS, Linux, and Windows (Windows Terminal, PowerShell, Git Bash/WSL), relying on `chalk` to resolve ANSI color capability rather than emitting raw escapes unconditionally.

### NFR-3: Node.js 18+ runtime baseline
**Tags:** NFR-3, runtime, compatibility

The project targets Node.js 18 LTS or newer and uses only APIs available in that baseline. The supported engine range is declared in `package.json`.

## Architectural Decisions

### AD-1: Hardcoded ASCII-art glyphs
**Tags:** AD-1, ascii-art, dependencies
**Resolves:** FR-1, NFR-1

ASCII-art letterforms are defined as in-repo string constants (a per-character glyph map composed row-by-row) rather than generated by an external library. This keeps the dependency footprint minimal and the output deterministic.

### AD-2: chalk for color output
**Tags:** AD-2, color, portability
**Resolves:** FR-2, NFR-2

Color is applied via the `chalk` library, which negotiates terminal capability and emits portable ANSI sequences. The rainbow palette is expressed through chalk color styling rather than hand-written escape codes.

### AD-3: Single-file CLI with package.json start script
**Tags:** AD-3, cli, structure
**Resolves:** FR-3

The application is a single Node.js entrypoint (`index.js`) that composes the banner and writes it to stdout in one pass. `package.json` defines a `start` script aliasing `node index.js` so both invocation paths share one code path.

### AD-4: Built-in test runner
**Tags:** AD-4, testing, dependencies
**Resolves:** FR-4, NFR-1

Tests run on the Node.js built-in test runner (`node:test`) with `node:assert`, requiring no external test framework. Banner-producing logic is structured as an importable function so it can be invoked and asserted on without spawning a subprocess.

### AD-5: No flags, config, or persistent state
**Tags:** AD-5, scope, behavior

The program accepts no arguments, reads no configuration, and holds no state between runs. Behavior is fixed: produce the rainbow "HELLO WORLD" banner and exit. This boundary keeps the surface aligned with the single-sprint scope.

## Design Decisions

### DD-1: Rainbow spectrum order
**Tags:** DD-1, color, palette
**Resolves:** FR-2

The color cycle is ordered red → orange → yellow → green → cyan → blue → purple, then loops. This fixed seven-step sequence defines the visual identity of the banner.

### DD-2: Per-letter color cadence
**Tags:** DD-2, color, cadence
**Resolves:** FR-2

Color advances one step per rendered letter (the space between words is skipped for coloring), so adjacent letters always differ in hue and the spectrum repeats predictably across the eleven letters of "HELLO WORLD".

### DD-3: Centered, padded layout
**Tags:** DD-3, layout, output
**Resolves:** FR-1

The banner is presented as a centered block with a blank line of padding above and below, written to stdout, so the greeting stands clear of the surrounding prompt.

### DD-4: Static single-frame output
**Tags:** DD-4, output, scope

The banner is printed in a single synchronous frame with no delays, redraws, or animation. The character-by-character reveal idea is intentionally excluded from v1 to preserve the minimal, deterministic output.
